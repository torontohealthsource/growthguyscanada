# Why some codes persist for years and others die in a week

A code issued to acquire a specific customer -- a first-order welcome, a one-time recovery offer -- is built to be short and often single-use.

## Two kinds of code, two lifespans

A code issued to acquire a specific customer -- a first-order welcome, a one-time recovery offer -- is built to be short and often single-use. A code published as a standing arrangement is maintained because it is doing continuous work. Lifespan follows purpose, and purpose is usually visible from where the code was published.

## A code without a published expiry is not permanent

It is undated. Those are different things. An undated code can stop working at any time without anything on any page changing, which is the entire reason a dated reading has value: it narrows when the code was last known to work.

## Where a code is published tells you its purpose

A code appearing in a seller's own checkout flow is doing acquisition work. One circulated through third parties is doing reach work and is usually maintained longer, because withdrawing it leaves stale references everywhere.

## Why stacking rules change more often than codes

Sellers adjust how offers combine far more frequently than they withdraw a code. A code that still applies but no longer combines with something has changed materially while appearing unchanged. A test recording only whether the code was accepted will miss this; one recording the resulting total will not.

## Silent changes are more common than withdrawals

A code that still applies but at a different percentage has changed in the way that matters while remaining active by any test that only checks acceptance. This is the single most common way a published figure goes wrong.

## What a reader should keep

The total, not the percentage. A percentage can be recomputed from a cart total; a total cannot be recovered from a percentage, and it is the total that was actually observed.

## What a reader can reasonably conclude

That a code worked at a stated time, on a stated cart, at a stated total. Everything beyond that is an expectation about the future, and should be written as one.

## Duration is a merchant decision, not a property

Codes end when a seller decides they end, and no published duration is binding unless stated as a term. A code described as permanent is describing an intention.

## Dated testing is the only reliable answer

Whether a code works today is answerable only by a test today. Any claim about current validity that is not attached to a recent date is an inference from the past.
