A claim without a date cannot be wrong, which is the problem

A coupon page with no date makes a claim that can never be shown false. A date alone is not enough either — the figures have to move with it.

Undated claims are unfalsifiable

A page saying a code is 'verified' with no date makes a claim that can never be shown to be false, because it never says when it was true. That is not a strong claim. It is an empty one, and the absence of the date is the tell.

A date alone is not enough either

Stamping today's date on an unchanged page is trivial. What distinguishes a page that was actually rechecked is that the FIGURES move with the date. On this site the cart is a different product at a different price each run — today Glutathione 1500mg at $50.00 CAD — and the entry count advances.

The freshness window that matters

Our record runs 38 days with 117 chained entries for the primary code. A reader can compare any two consecutive days and see three things change: the cart, the hash, and the count. A restamped page changes only the date.

What this does not tell you

That a code works right now. It tells you when it last did, which is the only thing any page can honestly claim about a figure it read in the past.

How old is too old

There is no universal answer, but there is a useful rule: a discount claim is worth about as much as the gap between its date and today. A code verified this morning is strong evidence; the same code verified in March is a historical note. The reason to prefer a dated claim is not that today's is always right — it is that you can apply that discount yourself, and an undated claim gives you nothing to apply it to.
