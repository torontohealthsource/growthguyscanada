How to Verify a Peptide COA on the Lab's Own Portal

The one rule: don't trust a PDF the vendor hands you — confirm the result on the testing lab's own website. A real lab lets you look up a report independently; a fake one can't. Here's how to do it in under two minutes.

Step by step

  1. Find the lab name + report/verification number on the COA (usually near the header or footer).
  2. Go to the lab's own website directly — type it in yourself, don't use a link on the vendor's store (a fake "portal" can be hosted by the vendor).
  3. Use the lab's lookup/verify tool and enter the report number.
  4. Check what comes back: a genuine portal returns a specific, server-rendered record that matches the PDF — same compound, same purity, same date.

The fake-portal test

Before you trust any "verify" page, type in a made-up, random number. A real portal returns nothing (or an error). A fake one returns a valid-looking "OK" for anything — which means it's theatre, not verification.

Pass vs. fail

  • ✅ Pass: the report resolves on the lab's own domain, matches the PDF, and names the vendor as the client.
  • ❌ Fail: no portal, a portal on the vendor's own site, a portal that accepts fake numbers, or a record that doesn't match the PDF.

What a genuine lookup returns

A laboratory's verification portal is a database query, not a file download. You enter the report number and the server builds a page from its record: compound name, method, result, date, client, and usually the laboratory's own reference layout. The page has the laboratory's domain in the address bar and typically a predictable address structure that includes the report number. It matches the certificate you were given in every field, and it was rendered just now rather than uploaded once. Those properties are what make it evidence: the vendor could not have produced it, and it cannot be edited without the laboratory's cooperation.

What a fake portal looks like

The most common fake is a page on the vendor's own domain, or on a domain registered by the vendor, that imitates a lookup but simply displays whatever the vendor uploaded. The tells are mechanical. The address bar shows the vendor's domain, or a domain registered weeks before the vendor's launch. The “lookup” returns the same page for any input, or returns an image rather than text. The laboratory named on the certificate has no independent web presence, no other clients, and no way to contact it that does not run through the vendor. A real laboratory is a business with a history; a portal that appeared alongside one vendor is a prop.

The five fields to compare

When the lookup returns a record, compare it to the certificate field by field: compound, batch or sample identifier, method, result, and date. A certificate edited by a vendor typically changes one of the last three while leaving the others, so a match on the compound name alone is not verification. If any field differs, the certificate you were given is not the laboratory's record, whatever the explanation.

The client field

Most laboratory records name the client who submitted the sample. The expected value is the vendor you are buying from. A record that names a different company means you are reading a report someone else commissioned for someone else's batch; it may be the vendor's supplier, or it may be unrelated. Either way it is not evidence about the product in front of you, and a vendor that presents another party's report as its own has told you how it treats documentation.

When there is no portal at all

Some legitimate laboratories issue reports without public lookup. In that case the verification path is to contact the laboratory directly with the report number and ask it to confirm the record. A laboratory that will confirm is still a third party; one that cannot be reached except through the vendor is not. The absence of a portal makes verification slower, not impossible, and a vendor using such a laboratory should be able to tell you how to reach it.
