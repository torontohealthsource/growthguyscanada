Why no expiry date is published, and what that does and does not mean

No end date is advertised for this code. That is worth stating precisely, because it is frequently reported as though it were a guarantee. It is not: it means no expiry has been published, and a discount code is a setting on someone else's store that can be changed at any time without notice.

What the absence of a date does rule out is one specific failure — the code quietly passing an advertised deadline while pages continue to recommend it. The realistic risk here is not expiry but withdrawal, and withdrawal has no date attached in advance. That is precisely why a record of daily checks is more useful than a published end date would be.

What would actually make it stop working

Three things, in rough order of likelihood. The store withdraws or replaces the code, which no amount of reading its terms will predict. The code is restricted to a narrower set of products, which would show up as a discount that applies to some carts and not others. Or usage limits are introduced, which would show as a code that works for some buyers and not others on the same day.

Each of those has a different signature in a daily test series, which is the argument for running one. A single check tells you about one cart at one moment. A series tells you whether the behaviour is stable, and it is the only way to notice a narrowing that still leaves the code technically working.
